## Integration Check Results

### Critical Gaps

**GAP-1 (CRITICAL — PLAT-02): No `/health` route in Admin API**

Three inconsistent healthcheck definitions exist with only docker-compose working:

| Environment | Healthcheck | Result |
|-------------|-------------|--------|
| docker-compose.yml | TCP socket port 8000 | ✓ Passes |
| Dockerfile line 44 | `GET /api/v1/servers` | ✗ 401 Unauthorized |
| services.tf line 143 | `GET /health` | ✗ 404 Not Found |

The ECS task definition health check calls `http://localhost:8000/health` which returns 404. ECS will cycle the admin-api task indefinitely, preventing healthy state. The fix is a single unauthenticated `GET /health` route in `switchboard/admin/app.py` returning 200, aligned across all three healthcheck definitions.

**GAP-2 (HIGH — CONT-04): HealthMonitor HTTP probe missing Cloud Map domain**

`switchboard/health/monitor.py` line 140:
```python
url = f"http://{CONTAINER_NAME_PREFIX}{server_name}:8000/mcp"
# Produces: http://sb-echo:8000/mcp (correct locally)
# ECS needs: http://sb-echo.switchboard.local:8000/mcp
```

The gateway proxy correctly reads `settings.cloud_map_domain` via `resolve_backend()` (`proxy.py` line 72), but the health monitor constructs its URL directly without that suffix. In production ECS, every HTTP probe fails with `httpx.TransportError`, triggering the degraded → unreachable state machine for all running servers within 2 poll cycles.

### Minor Issues (Non-blocking)

**MINOR-1 (LOW — Design inconsistency):** Gateway ECS task definition (`services.tf` line 39) injects `DATABASE_URL` from Secrets Manager. The gateway is stateless and never opens a database connection (per Phase 5 Plan 03 SUMMARY decision D-08). This grants unnecessary Secrets Manager read access and adds unused environment variable.

### Connected Flows (Confirmed Working)

**Flow 1 ✓ — Operator lifecycle (local):** Register server → start container → health monitor picks it up → GET /api/v1/servers returns health_status

**Flow 2 ✓ — Customer MCP request:** JWT validation → server name validation (SSRF prevention) → resolve_backend → httpx proxy → StreamingResponse with hop-by-hop filtering

**Flow 3 ✓ — Docker Compose:** All 5 services start in correct order with working healthchecks; gateway resolves sb-echo/sb-ping via internal bridge network

**Flow 4 ✗ — AWS production (PLAT-02 + CONT-04):** Admin-api can't reach healthy state (missing /health route); health monitor marks all containers unreachable (missing cloud_map_domain)
