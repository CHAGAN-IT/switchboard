       ```python
       @router.post(
           "/servers/{name}/start",
           response_model=ServerRead,
           summary="Start a server container",
       )
       async def start_server(
           name: str,
           session: Annotated[AsyncSession, Depends(get_session)],
           repo: Annotated[ServerRepository, Depends(get_repository)],
           cm: Annotated[ContainerManager, Depends(get_container_manager)],
       ) -> ServerRead:
       ```
       Implementation:
       - Look up server: `server = await repo.get_by_name(session, name)`
       - If None: raise `HTTPException(status_code=404, detail=f"Server '{name}' not found")`

       - Try: `server = await cm.start(session, server, repo)`
       - Except `ContainerStartError` as exc: raise `HTTPException(status_code=500, detail=str(exc))` from None
       - `await session.commit()`
       - Return `ServerRead.model_validate(server)`

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-07 | Spoofing | Lifecycle endpoints | mitigate | All endpoints protected by `require_operator` JWT dependency (router-level). Verified by `test_*_no_auth_401` tests. |
| T-3-08 | Information Disclosure | Error responses | mitigate | Use generic `{"detail": "..."}` format per D-04. ContainerStartError message includes server name and reason but NOT Docker internal details. |

| T-3-10 | Repudiation | Lifecycle operations | accept | No audit logging in Phase 3. Structured logging deferred to Phase 5 (OBSV-01). Operations are traceable via registry status changes. |
</threat_model>
