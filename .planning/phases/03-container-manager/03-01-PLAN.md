<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin API -> ContainerManager | Operator-authenticated requests trigger container lifecycle operations |
| ContainerManager -> Docker daemon | Application process communicates with Docker daemon via Unix socket |
| Docker daemon -> host OS | Docker daemon has root-equivalent access to the host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Elevation of Privilege | ContainerManager.start() | mitigate | Never pass `privileged=True` or add capabilities to `containers.run()`. Verified by unit test asserting no `privileged` kwarg. |
| T-3-02 | Information Disclosure | ContainerManager.start() | mitigate | Never pass `ports=` parameter to `containers.run()` per D-01. Verified by unit test `test_start_no_host_ports`. |
| T-3-03 | Tampering | ContainerManager.start() | mitigate | Container image comes from `server.container_image` which is operator-controlled via authenticated Admin API (require_operator JWT). No user-supplied image names at runtime. |
| T-3-04 | Elevation of Privilege | Docker socket access | accept | Docker socket access grants root-equivalent privileges. Accepted for local dev; in production (Phase 7), ECS replaces Docker SDK entirely. Documented in SECURITY.md. |
| T-3-05 | Denial of Service | ContainerManager.start() | accept | No rate limiting on lifecycle endpoints in Phase 3. Access limited to authenticated operators (trusted). Rate limiting deferred to v2 (SECU-04). |
| T-3-06 | Tampering | Container naming | mitigate | Container names use `sb-` prefix + validated server name (regex `^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$` enforced at model level). Prevents injection of special characters into Docker API calls. |
</threat_model>
