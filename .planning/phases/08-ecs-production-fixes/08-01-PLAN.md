<objective>
Fix two production-blocking gaps so the admin-api ECS task reaches healthy state and the health monitor correctly probes MCP server containers via Cloud Map DNS.

Purpose: The v1.0 milestone audit identified that (1) the admin-api has no unauthenticated /health endpoint, causing the ECS healthcheck to fail with 401 and cycle the container indefinitely, and (2) the health monitor constructs probe URLs without the Cloud Map domain suffix, so probes fail in ECS where DNS names require `.switchboard.local`.

Output: Fixed admin-api that passes ECS healthcheck, fixed health monitor that probes containers in both Docker Compose and ECS environments, aligned healthcheck definitions across Dockerfile, docker-compose.yml, and services.tf.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ECS healthcheck -> /health | ECS container agent sends unauthenticated HTTP request to the admin-api /health endpoint |
| External network -> admin-api | Admin-api is internal-only (not registered with ALB per services.tf line 157); security groups restrict ingress |
| Health monitor -> MCP server containers | Monitor sends HTTP POST to backend containers via Cloud Map DNS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8-01 | Information Disclosure | /health endpoint | mitigate | Return only `{"status": "ok"}` -- no version, config, environment, debug info, or database status. Test `test_health_response_minimal` enforces this by asserting `set(data.keys()) == {"status"}`. |
| T-8-02 | Denial of Service | /health endpoint | accept | Minimal response body (26 bytes), no database queries, no computation. ECS ALB rate-limits at infrastructure level. Admin-api is not ALB-registered (internal-only per services.tf line 157), reducing external attack surface. |
| T-8-03 | Information Disclosure | /health external access | mitigate | Admin-api ECS service is NOT registered with the public ALB (services.tf line 157-177). Security groups restrict ingress to VPC-internal traffic only. No additional code mitigation needed -- infrastructure enforces boundary. |
| T-8-04 | Spoofing | Cloud Map DNS resolution | accept | Health monitor trusts Cloud Map DNS within the VPC. DNS poisoning within a private VPC requires compromised VPC infrastructure, which is outside the application threat model. AWS Cloud Map provides authenticated service registration. |
</threat_model>
